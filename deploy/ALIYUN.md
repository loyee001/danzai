## 本地生成发布包

```sh
python3 deploy/prepare-aliyun.py
```

输出 `artifacts/danzai-aliyun-*.tar.gz`、包摘要和 `danzai-manifest.json`。
归档包含 22 个静态文件及校验清单，不包含项目其他内容；脚本会重新打开成品逐文件校验。

## 确认服务器后的流程

1. 只读检查系统、Caddy 服务、当前 IP 站点路由以及目标入口是否已存在。
2. 将发布包和安装脚本传入服务器私有临时目录，再以实际包名和 SHA-256 运行
   `bash aliyun-static-install.sh --check PACKAGE SHA256`。
3. 预检必须确认当前 IP host 是无路径限制的静态根。若配置不同则停止，先审阅真实配置。
4. 运行同一命令的 `--install` 模式。文件进入新的 `.danzai-release.*` 目录，
   校验后原子切换独立 `danzai` 链接；旧版本目录保留。
5. 安装脚本逐一核对 Caddy 实际返回的 22 个文件，任何失败自动恢复旧入口。
   不重启或重载 Caddy。私有临时目录保留校验清单和记录。
6. 从公网独立检查 HTTP 状态、MIME、22 个内容摘要、`/danzai` 到 `/danzai/` 的跳转，
   再验证 50 关大厅、传送门、零库存拾取、咸鱼和三键复位。

上线前需检查响应缓存策略。未带内容哈希的 HTML/JS/CSS 应重新验证缓存；如果现有站点
不满足要求，不能擅自覆盖共享配置，应先准备仅针对本游戏路径的配置变更。

本次是浏览器静态游戏，不需要 Node 后台、数据库、Docker 或真实广告网络。
HTTP/IP 下复制地图码可能使用文字提示回退；新网址与 localhost 的存档相互独立。
